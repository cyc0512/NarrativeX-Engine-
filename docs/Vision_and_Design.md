# NarrativeX Engine：FluidStory 品类愿景与设计

## 一、核心理念：为什么需要 FluidStory

文字游戏（Visual Novel）走到今天，陷入了一个结构性的瓶颈：**分支靠手写**。

静态分支树的成本随结局数线性甚至指数增长——每多一个结局，就要多写一整条线。于是市面产品要么分支浅薄、要么靠堆量取胜，体验高度同质化（我们称之为"滥而多"）。而另一端的纯 AI 角色扮演虽然自由，却普遍面临失忆、人设崩塌、时间线错乱（吃书），玩家很难从中获得"故事"的重量。

FluidStory（流态小说）是为打破这个两难提出的新型叙事品类。我们无意做"更自由的聊天"，而是把体验感押在一个更古老、更有力的动机上——**宿命感**：玩家反复探索，只为回答那句"如果当时那样说，会不会是另一种结局"。

由此引擎确立了两条设计原则：

- **骨架由作者写定**：时间线、关键节点、结局归作者所有，保证故事的重量与可控。
- **血肉由 AI 扮演**：角色的每句话由 AI 依人设、情绪与玩家输入实时生成，保证生命的质感。

## 二、定位取舍：为什么是"半开放"

半开放相对全开放 AI 是**刻意保守**的，这份保守正是卖点：

| 维度 | 静态分支树 | 全开放 AI 陪伴 | FluidStory（半开放） |
|---|---|---|---|
| 主线与时间线 | 完整但僵化 | 松散、易吃书 | 作者写定，动态节点按锚点插入 |
| 角色台词 | 固定、无生命 | 鲜活但易崩人设 | 依人设扮演，内敛且紧扣输入 |
| 重玩驱动 | 分支数量 | 新鲜感递减 | 宿命感："换个说法会不会改写结局" |
| 创作者成本 | 手写穷举所有线 | 只调 prompt | 声明节点 / 意图 / 角色库 |

半开放不是折中妥协，而是明确回答：**自由必须发生在骨架之内，否则不成其为故事。**

## 三、引擎两大能力

### 能力一：让角色活过来（AI 扮演层）

角色的说服力来自三件事，全部做成可配置：

1. **人设分库**：每个 NPC 一个 prompt 库（persona / 视角契约 / 专属情绪词条 / 对话样例 / 违规判定），发 AI 时按说话人只装载对应库。木子因的内敛不会污染林如夕的活泼，新增角色只加一个 JSON 文件。
2. **第一人称视角契约**：AI 以"我"说话、称呼对象固定（木子因叫哥哥、林如夕叫前辈），能识别玩家的明知故问（如"你是谁"）并察觉反常，而不是机械镜像复读或荒谬自报家门。
3. **情绪只做微调**：情绪标签仅扰动语气轻重，绝不覆盖人设与说话方式；内敛角色心里翻涌、嘴上轻描淡写，用省略号与日常小动作承载潜台词。

### 能力二：让分支活起来（动态调度层）

玩家的自由输入是一等公民。一句输入经过如下链路变成剧情推进：

```
玩家自由输入
  → L0 关键词强控（0 token）/ L1 本地相似度（0 token）
  → L2 受限大模型（合法后继白名单单选，可弃权）
  → 意图命中 → Fixed / Dynamic / Preposable 节点调度
  → 多结局收束（违规累积 / 关键标签 / 输入共同决定）
```

- **三分类节点**：Fixed（固定演出）、Dynamic（条件触发）、Preposable（可前置到锚点时间线）。
- **闸门与白名单**：节点合法性由 `Frontier` 闸门与意图白名单保证，不依赖旧式拓扑锁。
- **弃权不降级**：L2 模型无把握时可弃权（abstain），原地停留而非强行选 Top1，宁可克制不可错判。
- **玩家输入即命运动作**：自由输入是触发隐藏节点与结局分支的主要方式，而非在固定选项里三选一。

## 四、大模型职责界定（受限使用）

为杜绝幻觉与越权，大模型在引擎中只是受限工具：

1. **意图选择器**：只在白名单内做单选，可弃权，不自由发挥剧情。
2. **情绪分析器**：从预设标签中提取情绪，不改写人设。
3. **角色扮演器**：注入人设、视角、情绪与历史，生成第一人称台词，禁 JSON 与旁白。
4. **违规守卫**：独立判定玩家是否偏离扮演身份，只对木子因线累积坏结局计数。

## 五、现状与演进

> 本文是品类愿景。以下为当前已落地与待建设的分界，避免把愿景误当现状。

**已落地**：
- 意图分级漏斗、三分类节点、闸门与白名单、违规守卫
- 按角色 prompt 分库 + 兼容回退
- 第一人称视角契约、情绪微调、20 字规则反思
- 多结局与坏结局动态节点（`n_bad_doll`）

**待建设（方向，非现状）**：
- 更多动态节点与结局分支线：当前剧本动态节点仅 1 个，需持续扩充内容
- `history_tail` 真实台词写回（让 AI 读到玩家真正看到的对话，而非默认台词）
- 发行级后端代理（API Key 不下发客户端、限流、配额、429 退避）
- 基于向量的 L1 匹配（同义不同词的零延迟本地命中）

## 六、给创造者的新思路

NarrativeX 想提供的不是又一款视觉小说，而是一套让**"台词有生命 + 分支会流动"成为可配置能力**的引擎。

创作者不再手写穷举每句话、每条线，而是：
1. 声明节点、意图与结局（数据驱动，不改 C++）；
2. 为每个角色写一份 prompt 库（人设、口吻、情绪、违规边界）；
3. 把演绎交给引擎与 AI。

这样，创造者得以把精力放在最该由人做的事上——**设计命运，而非穷举命运的所有说法**。
