# NarrativeX Engine：FluidStory 架构愿景与设计

## 一、 核心理念：什么是 FluidStory？

传统文字游戏（Visual Novel）的底层是“静态树状图”，玩家的交互被锁死在预设选项中。而目前的 AI 角色扮演（如各类陪伴 App）虽然实现了自由输入，却往往缺乏主线约束，长对话后极易出现人设崩塌和时间线错乱（吃书）。

**FluidStory（流态小说）** 是 NarrativeX 引擎驱动的新型叙事品类。我们以**“大模型自由语义”为血肉**，以**“动态状态机（nx 内核）”为骨架**，致力于实现高自由度与宿命感并存的游戏体验。

## 二、 引擎核心分层架构

系统采用严格的分层设计，各司其职，互不干扰：

### 1. 行为表现层（Immediate Interaction）
- **基础交互**：玩家点击固定选项时，直接跳过 AI，读取剧本台词（0 延迟），确保游戏交互的下限与流畅度。
- **自由对话**：玩家可随时输入任意文本。引擎将结合当前场景（`npc_state`）、历史记忆（`summary`）和动态情绪标签（`tags`），调用大模型生成鲜活、符合人设的台词。
- **安全防线（拓扑锁）**：自由输入**默认不会引起剧情节点的跳跃**。如果 AI 试图将剧情跃迁至非相邻节点，拓扑锁会强行拦截，确保时间线不出现物理错乱。

### 2. 动态调度层（Dynamic Routing & Pointers）——【开发中】
- **双指针机制**：
  - **前移指针**：当玩家通过自由对话满足了特定条件（标签/道具），引擎可将时间线后方的关键节点“拉”到当前位置，提前爆发剧情。
  - **重归指针（事件挽回）**：过去错失的节点（如当时没敲门道歉）不永久消亡，而是进入挂起池。未来条件满足时，重新流动回主线。

### 3. 心理状态层（Emotional Tags）——【当前突破点】
- **场景化标签（Contextual Tags）**：剥离时效性的标签库。标签不写死“拒绝了去水族馆”，而是抽象为“玩家做出了拒绝且未安抚的冷漠行为”。通过大模型在对话时进行**动态心理判定**，提取通用情绪标签。
- **记忆沉淀**：每一次判定出的标签，不仅会记录标签名，还会记录其**诞生的上下文**（当时发生了什么）。在后续的台词生成中，AI 会读取这份心理档案，做到真正的“拟人化”回应。

## 三、 大模型职责界定（降级与受限）

为了杜绝 AI 幻觉，大模型在引擎中被拆分为三个受限的专用模型：

1. **路由分类器（Router）**：只在本地相似度极低时介入，从 Top-K 短名单中选一个，不能自由发挥。
2. **情绪分析器（Tag Extractor）**：根据上下文，从预设的通用标签白名单中提取当前情绪，不输出废话。
3. **台词生成器（Actor）**：注入完整的状态、记忆、标签上下文，生成符合设定的台词，禁止输出 JSON 及跳出角色。

## 四、 未来演进方向

- **基于向量的 L1 匹配**：在 L0（精确词）与 L2（大模型）之间，引入 Local Embedding，实现“同义不同词”的零延迟本地匹配。
- **动态标签权重**：放弃简单的标签 `0/1` 集合，引入“情绪值累积”。一句敷衍会增加 1 点失落，一句冷暴力的伤害会增加 20 点。
- **NPC 通讯录（异步交互）**：玩家可通过手机 UI 的形式，随时与已解锁的 NPC 发起聊天，不受限于当前剧情节点，进一步模糊“游戏”与“生活”的边界。
