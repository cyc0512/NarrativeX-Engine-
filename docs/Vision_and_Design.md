# Isolate Engine：架构设计与实现思路

## 一、 项目背景与目标
传统文字游戏依赖庞大的剧情树，玩家只能在有限选项中做选择。虽然使用大模型（LLM）可以打破这种限制，但如果完全让 AI 自由生成剧情，会导致逻辑失控、文学下限低、且无法收敛到固定结局。
本项目的目标是在 **C++ 本地状态机** 的控制下，利用 LLM 实现更灵活的意图识别，同时保证主线剧情的逻辑稳定。

## 二、 核心技术实现（已完成）

### 1. 网络通信与 UI 防阻塞
*   采用 `libcurl` 发送标准的 HTTP POST 请求与大模型（如智谱 GLM）通信。
*   由于大模型响应延迟通常在 1-3 秒，为防止 Qt 主线程卡死，引入了 `QtConcurrent` 多线程框架。UI 界面在发起请求时进入“思考中”状态，后台线程接收 JSON 返回值后，再通过信号槽机制更新 UI。

### 2. 数据持久化与平滑迁移
*   采用 SQLite 存储玩家数据。为了防止版本更新导致旧存档失效，在 `DatabaseManager` 中实现了数据库结构自动迁移（通过 `PRAGMA table_info` 检查字段，缺失则执行 `ALTER TABLE`）。
*   存档列表通过 SQL `ORDER BY last_login DESC` 按时间降序渲染。

## 三、 正在攻关的架构难点（开发中）

### 1. 动态状态注入 (Dynamic State Injection)
*   **痛点**：目前 AI 的人设是静态的，导致 NPC 在整个游戏流程中性格一成不变，缺乏成长或变化。
*   **方案**：改造 `story.json` 结构，在每个剧情节点增加 `npc_state`（如：“强装镇定”、“极度焦虑”）。C++ 引擎在调用 AI 前，提取该节点的状态，与玩家输入一起拼接成动态 Prompt。使同一个问题，在不同节点触发时，AI 给出符合当前心理状态的反应。

### 2. 主线收束机制 (Mainline Convergence)
*   **痛点**：AI 的自由生成缺乏下限，如果玩家输入极端言论，AI 可能无法给出符合游戏设计逻辑的反应。
*   **方案**：在 Prompt 中设定 AI 的“底线判定”。当 AI 识别到玩家试图打破核心关系（如“离开”）时，返回特定的 `trigger_event` 标识。`GameEngine` 拦截该标识，打破原有的按节点顺序推进的逻辑，强制将当前节点强制跳转（收束）至预设的 BAD ENDING 节点，确保游戏内容的不可逆性与剧情张力。
