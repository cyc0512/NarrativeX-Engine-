# NarrativeX Engine：架构设计与愿景

## 一、 项目愿景 (Project Vision)

我们正在开发一款基于大语言模型与状态机深度结合的新型交互式小说引擎（FluidStory 流态小说）。

传统视觉小说的核心依赖静态分支树，玩家的交互被严格限制；而目前的 AI 角色扮演产品虽然实现了自由输入，却缺乏主线目标，且随着上下文激增，极易出现“对话断层”与人设崩塌。

**NarrativeX 的愿景，是打破这两种极端的僵局：**
将大模型的“语义理解能力”与本地 C++ 状态机的“强逻辑约束”融合。玩家可以用自然语言与 NPC 真实交流；同时，通过引擎底层的拓扑锁、动态指针与挂起池，确保所有交互最终收束至不可逆的宿命结局。

## 二、 核心架构：DSCR 机制

引擎摒弃了死板的静态树，实现了基于 **DSCR (Dynamic State & Convergent Routing)** 理念的半涌现叙事架构：

### 1. 意图分级漏斗 (Intent Hierarchical Funnel)
引擎将大模型从“创作者”降级为“受限分类器”，极大降低了延迟与幻觉：
- **L0 (关键词命中)**：`keywords` 暴力匹配，0 延迟直接路由。
- **L1 (本地语义)**：`examples` 字面相似度计算，本地处理。
- **L2 (受限选择)**：将当前可用的节点 ID 短名单交给大模型，模型只做单选题，不在名单内的一律降级。

### 2. 基础拓扑锁 (Topology Lock)
这是 FluidStory 保证时间线不崩塌的底线。
无论大模型在 L2 阶段做出了什么抉择，只要目标节点**不与当前节点直接相连**（即不在 `options` 或 `default_next` 中），引擎就会触发“拓扑锁”：
- 拦截跳转。
- 将状态回退到“原地”。
- 大模型使用**当前节点**的 `npc_state` 上下文来生成回复。

这意味着，玩家可以随意输入任何话，AI 会生动地接话，但**绝对不会发生时间悖论与剧情错乱跳跃**。

### 3. 动态拓扑与指针 (Dynamic Pointers)
如果玩家试图前往未来的节点（如提前触发结局），或者找回过去的节点（如弥补遗憾）：
- 引擎底层维护着“指针”机制（动态重连 `rewire`）。
- 只有当玩家累积的标签（如“病态的爱”）、道具满足了阈值，指针才会把这把“钥匙”发放给当前的短名单。
- 此时，拓扑锁才会放行，允许大模型跨越基础时间线，实现节点的“前移”或“回溯”。

## 三、 工程容错与多线程

- 采用 `libcurl` + `QtConcurrent` 将 AI 请求分流至后台线程，主线程利用 `QTimer` 实现 5 秒超时熔断保护。
- 彻底解决了网络阻塞导致的窗口“未响应”问题。
- 输入防抖（`aiInFlight`）确保同一时刻只有一条请求在飞。
- 数据库采用 `PRAGMA table_info` 自动迁移机制，旧存档无缝兼容。底层状态直接序列化为 JSON 存入 `state_json` 列，实现了全量状态机的持久化。

## 四、 总结

**NarrativeX** 是一套完备的底层引擎。我们证明了：自由输入并不等同于“脱缰的野马”。通过巧妙的分层漏斗与拓扑锁机制，我们可以同时拥有文字游戏严密的逻辑底线，以及大模型带来的无限涌现交互。
