## 🌟 项目愿景 (Project Vision)

### 突破传统文字游戏的“交互困境”
随着大模型（LLM）性能的飞跃与算力的普及，AI 已经能无缝融入日常生活。然而在当前的游戏市场中，AI 多倾向于被用作“数据整合”或“智能客服”的工具，而非真正的游戏核心。我们认为，**AI 最强大的对话交互与文本意图识别能力不应被浪费。**

传统文字冒险游戏（Visual Novel）通常依赖固定的选项与线性剧情引导玩家。这种模式虽然在短期内能提供代入感，但极大限制了玩家的发挥空间，导致游戏结束后常伴有“内心亏空”感，且复玩性（Replayability）极低。

### 💡 我们的破局方案：AI 驱动的深层交互与隐藏支线
本项目的核心理念是：**用自然语言交互替代僵化的选项，用复杂的分支网络填补剧情深度。**

1. **打破选项桎梏**：保留基础选项以保证游戏下限，但大量引入玩家自由输入。
2. **极高门槛的隐藏分支**：我们计划设计一系列极难解锁的分支条件。当固定的选项无法满足条件时，玩家必须通过**“哄好 AI NPC”**，或者在长时间、跨节点的高质量沟通后，才能触发隐藏支线或真结局。
3. **深度嵌合的成就感**：将“玩家输入自由度”与“隐藏结局解锁”深度嵌合。玩家不再是为了选对答案而玩游戏，而是为了探索 AI NPC 的情感边界。

## 核心系统架构：AI 驱动的状态机 (AI-Driven FSM)
本项目采用了“本地状态机 + 云端大模型”的混合双引擎架构。
### 1. 双轨制分支触发机制
*   **机制 A：状态阈值判定（稳定可预期）**
    引擎通过 SQLite 记录玩家状态（好感度、隐藏依赖值）。当数值跨越特定阈值时，自动改变节点流转逻辑。
*   **机制 B：语义事件拦截（高自由度）**
    大模型在返回自然语言回复的同时，会输出结构化 JSON（包含 `trigger_event` 字段）。当系统捕获到特定事件（如玩家提及了敏感人物），引擎会强行拦截当前流程，切入隐藏支线。
### 2. 提示词工程与结构化输出 (Prompt & JSON Output)
为保证系统能理解玩家意图，我们通过 `System Prompt` 为 AI 定义了极强的人设约束，并强制其返回标准的 JSON 格式：
`{"affinity_change": 5, "trigger_event": "none", "reply": "..."}`
确保前端的 UI 渲染和底层的逻辑判定能够精准解耦。
### 3. 性能与成本控制 (Performance Control)
*   **异步多线程**：使用 Qt 多线程技术，将 LLM 的推理延迟与 UI 渲染线程分离，确保网络请求期间客户端界面依然保持 60 FPS 丝滑响应。
*   **正则前置过滤**：避免无效文本（如无意义的乱码）直接消耗大模型算力。
